# 鲜记 · 冰箱食材管家

> 把冰箱里的事，记清楚。

一个用 Python + SQLite 做的本地冰箱库存小应用。像记账一样，记下每件食物放在哪一格、还剩多少、什么时候到期、怎么做，临近过期时提醒你先吃掉。

界面是移动优先的响应式 Web App，电脑浏览器和手机浏览器都能用，也可以从手机浏览器“添加到主屏幕”。

![鲜记桌面端首页](docs/screenshots/home-desktop.png)

## 为什么做这个

你提到的几个场景，几乎就是产品需求本身：

- 老人和普通家庭都会囤东西，冰箱越塞越满，最后忘了里面有什么；
- 分装之后把原包装扔掉，保质期、加热时间、做法也跟着丢了；
- 知道“好像快过期了”，但不知道具体是哪天、哪一件；
- 想知道今天吃得怎么样，但不想再做一份复杂的饮食日记。

“鲜记”把这些变成一条很短的记录链路：**放在哪 → 还剩多少 → 什么时候吃完 → 怎么吃 → 吃掉它**。

![全部食材](docs/screenshots/inventory.png)

## 已经实现的功能

### 1. 冰箱地图，记到具体隔层

默认带有冷藏室上/中/下层、果蔬抽屉、门架、冷冻室上/下层、变温抽屉。每个存放格都能看到：

- 放了几件、建议容量；
- 哪些快到期、哪些已经过期；
- 直接在这个格子里添加食材；
- 在设置里增删自定义存放格。

### 2. 食材档案：数量、日期、做法

每件食材记录名称、分类、数量、单位、存放格、保质期、做法、温度、时间、做法小抄和备注。

常用食材带有默认值：输入“鸡翅”，会自动补上分类“肉禽”、单位“袋”、默认做法“空气炸锅 200°C 18 分钟”；根据你选的冷藏或冷冻格，给出不同的默认保质天数。**这些只是默认建议，最终永远以包装和实际状态为准。**

### 3. 先吃清单与临期提醒

- 首页按到期时间排出“先处理这几件”；
- 过期、今天到期、3 天内到期分别用不同颜色标识；
- 每条库存都有 `吃掉`、`全部吃完`、`丢弃` 三种处理方式；
- 丢弃会进入浪费统计，不会悄悄消失；
- 提醒页可以导出 `.ics` 日历文件，导入手机日历后，按设置的天数在到期前提醒（默认提前 3 天，并在前一天上午 9 点再提醒一次）；
- 日历提醒不依赖网页一直开着，比浏览器通知可靠。

### 4. “今天吃得怎么样”：食物组搭配，不是健康打分

把冰箱食材按四类记录：**蔬菜、蛋白质、主食、水果**。

吃完一件食材并记录后，今日页会显示：

- 今天覆盖了几类食物；
- 哪一类还没吃到；
- 下一餐可以补什么；
- 今天的做法统计，比如“水煮 × 2、微波 × 1”。

它不会给你一个虚高的“健康分”，也不会评判某一种食物“好坏”。页面明确提示：这只是饮食搭配记录，不构成营养或医疗建议。

![今日饮食](docs/screenshots/today.png)

### 5. 下一餐建议：优先用掉临期食材

用现有库存拼出 3 个可执行的搭配，比如番茄炒蛋、青菜豆腐汤、水果酸奶杯。

- 优先使用临期食材；
- 自动提示“再配一份主食 / 加一份蔬菜”；
- 可以点“换一道”轮换；
- **不会推荐已经过期的食物**。

### 6. 标签打印，解决“包装扔了”的问题

标签页会为每件食材生成一张小标签，包含名称、位置、数量、到期日、剩余天数、做法和备注。A4 纸 100% 缩放可以排下 8 张，沿虚线剪开贴在分装袋上。

### 7. 本地优先

- 数据存在本机 SQLite：`data/xianji.db`；
- 没有账号、云端上传、广告或第三方统计；
- 可以导出 JSON 全量备份、CSV 食材表；
- 低饱和暖色界面，没有外部字体和追踪脚本，离线也不会加载远程资源。

## 在 PyCharm 里运行

### 1. 打开项目

用 PyCharm 打开 `xianji` 这个文件夹（也就是包含 `run.py` 的目录），不要打开它的父目录。

### 2. 配置解释器

推荐 Python 3.10 或更新版本。

项目只有一个第三方依赖：**Jinja2**。

在 PyCharm 的 Terminal 里：

```powershell
python -m pip install -r requirements.txt
```

如果你在 PyCharm 里创建了虚拟环境，先把解释器切到该虚拟环境，再执行上面这条命令。已经装过 Jinja2 的系统 Python 也可以直接运行。

### 3. 运行

右键 `run.py` → **Run 'run'**。

也可以在 Terminal 里：

```powershell
python run.py
```

启动后访问：

```text
http://127.0.0.1:8765
```

默认会自动打开浏览器。想手动打开或后台运行，可以加参数：

```powershell
python run.py --no-browser
```

### 常用参数

```powershell
python run.py --port 8766          # 换端口
python run.py --no-demo            # 第一次启动不写示例数据
python run.py --db data/my.db      # 使用指定数据库
python run.py --debug              # 错误页显示 traceback
```

## 第一次打开

第一次启动会自动写入一份**示例冰箱**，方便你马上看到完整效果。首页顶部有一条提示，可以一键清空示例，换成自己的食材。

示例数据只删除带“示例”标记的记录，不会碰你自己新增的内容。

## 用手机打开

手机和电脑连同一个 Wi-Fi，然后：

```powershell
python run.py --host 0.0.0.0
```

查看电脑的局域网 IP（例如 `192.168.1.23`），在手机浏览器打开：

```text
http://192.168.1.23:8765
```

如果打不开，检查 Windows 防火墙是否允许 Python 访问专用网络。

> 注意：这个应用默认没有登录系统。`--host 0.0.0.0` 只适合在可信的家庭局域网中使用，不要把端口暴露到公网。

手机浏览器通常支持“添加到主屏幕”，打开后可以像 App 一样使用。

![手机端首页](docs/screenshots/home-mobile.png)

## 使用流程

1. **记一笔**：点“记一笔库存”，填名称、位置、数量和日期。常吃食材会自动带出默认值。
2. **吃掉一份**：打开食材详情，填吃掉的数量；系统会按当前时间记到早餐/午餐/晚餐/加餐。
3. **看今天**：今日页会汇总四类食物覆盖情况和下一餐建议。
4. **处理临期**：在提醒页/首页先吃清单中按到期时间处理。
5. **打印标签**：去标签页勾选需要的食材，打印后贴在分装袋上。
6. **导出日历**：在提醒页下载 `.ics`，用手机日历打开导入。

## 一些设计取舍

你的想法很完整，但有几个地方如果直接照做，容易变成“看起来很聪明、实际不好用”的功能。这个版本做了这些取舍：

### “健康”不做成评分

食物没有绝对的好坏，用 0–100 分给一餐打分很容易制造焦虑，也不严谨。这里只做**四类食物覆盖**和可执行的补充提示，并把免责声明放在显眼位置。

### 不用浏览器推送做主要提醒

纯本地网页没有服务器推送，浏览器关闭后通知不可靠。所以提醒的主路径是：

- 打开应用时看到醒目的临期清单；
- 把临期提醒导出到手机系统日历。

这样不需要部署服务器，也能获得真正的系统级提醒。

### 单机优先，多端同步留到后面

当前是一个无账号的单机应用，数据只在本机。这样做的好处是零配置、隐私好、在 PyCharm 里直接能跑。

如果以后要做“全家共享、多人同时记录”，需要加服务端、账号体系和权限；那是下一阶段的产品，不应该在第一版里假装已经解决。

### 不急着做扫码和 AI 识别

扫码、拍照识别食材当然很酷，但代价是识别错误、依赖外部服务、录入更慢。这个版本先把手动记录做到足够快：常用食物自动补全、默认日期、最近使用位置、明确的三步操作。等这些真实使用数据积累后，再决定要不要做识别。

### 保质期默认值不是权威结论

不同品牌、包装、冷链、开封状态都会影响实际保质期。内置的默认天数只是帮你少填几个字，页面始终提示“以包装说明和实际状态为准”。

## 数据与备份

数据库默认在：

```text
data/xianji.db
```

它不会提交到 Git。备份方式：

- 直接在“我的冰箱 → 数据与备份”导出 JSON；
- 或者停止应用后，复制 `data/xianji.db` 文件。

换电脑时，把项目文件夹和数据库一起复制过去即可。JSON 文件是人类可读的，但目前没有做“一键从 JSON 恢复”的界面；需要的话可以下一步加导入。

## 技术说明

- **Python 3.10+**：类型标注、`datetime.fromisoformat` 等；
- **Jinja2**：模板渲染；
- **wsgiref + ThreadingMixIn**：一个很小的本地 WSGI 服务，不引入 Flask/Django；
- **SQLite**：单文件、零配置、事务可靠；
- **原生 HTML/CSS/JS**：没有 Node、没有构建步骤、没有前端依赖；
- **PWA manifest + 图标**：支持“添加到主屏幕”；
- **CSRF token**：所有写操作都校验；
- **CSP / nosniff / frame 限制**：基础安全头。

### 为什么不用 Flask？

不是不能，而是这个项目的部署场景是“PyCharm 点运行、一个人本机使用”。用标准库的 WSGI 足够，还能把依赖压缩到 Jinja2 一个。真正需要多人同步、REST API、后台任务时，再换成 Flask/FastAPI 也不迟。

## 已知限制

- 单机使用，没有账号和多人同步；
- 不发送真正的后台推送，提醒依赖“打开应用”或“导入手机日历”；
- 没有从 JSON 恢复数据的界面；
- 没有条码/拍照识别；
- “营养搭配”只按四类食物做粗粒度提示，不计算热量、宏量营养素或个体化营养需求；
- 默认保质期是通用估算，必须结合包装和实际状态判断。
